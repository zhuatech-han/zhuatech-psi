# 商贸进销存操作手册

知华科技 · 上海如静知华信息科技有限公司 · https://www.zhuatech.cn/ · 商业咨询微信 zhuatech / zhuatech2。

## 准备档案和岗位

管理员先建部门、商品分类、仓库、商品、客户和供应商，再为员工建立账号。采购、销售、仓管与财务是独立岗位角色；管理员可按实际职责分配权限。业务主数据和仓库须同部门，客户仅用于销售，供应商仅用于采购。已有记录的部门、商品基本单位和往来类型不能改写，应另建档案；启停不删除历史凭证。

商品使用唯一编码和可选唯一条码。一个商品只有一个基本计量单位；数量最多三位小数，单价/金额最多两位小数，单次数量上限一百万，金额上限一万亿元。商品 JSON 导入最多 500 项，任一项校验失败全部回滚，模板不含库存或已发生的货款。

## 示例：100件采购、30件销售、2件退货

以下为虚构学习账，期初库存及往来款为零，无税费、运费和折扣。

1. 采购选择供应商、主仓和商品，数量 100、单价 10，保存草稿后确认。
2. 仓管第一次登记入库 60 件，第二次 40 件，各填写实际凭证号。库存 100 件、价值 1,000，应付 1,000。
3. 财务登记已实际支付的 600 元，应付余额 400。
4. 销售同一商品 30 件、单价 15，确认后分别登记出库 20 和 10 件。库存 70 件，应收 450。
5. 在原销售出库凭证上选择退货，登记可再次销售的 2 件及原因。库存 72 件、价值 720，应收 420、净销售成本 280、毛利 140。
6. 财务登记实际回款 200 元，客户未结余额 220。在往来对账选择客户查看逐笔变化；订单和对账 CSV 余额须一致。

开单扫码输入条码后回车或点击“扫码添加”，真实商品带出参考价格；同一商品只能有一行。确认后数量和价格冻结，需要调整时使用退货或价格贷记，不编辑数据库。

## 退货、价格调整与款项纠错

销售退货回到原仓，只适用于可售货物。损坏品需另行处理，此版不提供检验仓流程。按原出库凭证分配成本；分次退货的最终一笔带走对应金额尾差，累计不得超原履约量。退货不恢复可再次履约数量，要重新发货应另开订单。

采购退货按原收货凭证减少供应商应付，出库价值使用当前移动平均成本，因此可能与原采购金额不同。该差额在库存流水中可追溯，但此版不生成总账或采购价差利润报表。

“调价”只冲减某次原履约凭证的金额，不改变货物或成本。该凭证尚未发生实物退货时才可调价，累计不得超过原金额；后续实物退货按已经调价后的金额比例冲减，不能重复退款。不提供增加价格的借记调整。

已付款后退货/贷记可能产生负余额，即待退款。核对实际退款凭据，再登记退款；未实际退款不能把余额改成零。单据履约状态和货款余额分别核对。

款项录错点击原付款/退款凭证的“冲销”，填写新凭证号和原因；原记录不删除，并新增冲销记录。一笔原凭证只能冲销一次；若已有退款导致冲销原付款会把净付款降为负数，须先冲销有关退款，再冲销原付款。不能冲销冲销记录。

## 库存与盘点

期初库存只允许在该商品、仓库尚无任何库存流水时录入。之后用采购入库或盘点更正。盘点提交实盘量，同时检查打开表单时的账面量；期间发生收发货会拒绝提交，应刷新后重新核对。盘盈提供成本，盘亏沿用移动平均成本，零库存不留价值尾差。

调拨限同部门启用仓库，不允许负库存。调出、调入在同一事务里完成，价值一致，保留两条关联流水。确认订单不预占库存，出库时再次检查，因此销售员确认了订单仍可能遇到库存不足。

## 日常核对

核对单据履约、货款余额、原退货凭证、库存流水和对账记录。表格支持搜索、状态过滤、排序和分页；商品导入只新增，不覆盖已有档案。打印从已读取的真实单据生成，不插入推广内容。报表统计全期间实际已过账数据，草稿金额不计入净销售额；销售毛利不是扣除经营费用后的净利润。

操作失败会显示原因。网络状态不明时先刷新实际单据和台账，同一打开的动作表单保留请求标识，可原样重试；改变内容前先核对是否已成功。不要因未看到提示就重新登记真实付款。详细版本、依赖与安全事项见 README 和部署手册。
